05

脚本流程

  1. 检查 NAS 挂载，未挂载 → 记日志、退出非零、触发告警
  2. 逐库 pg_dump → gzip → 写 NAS postgres/<date>/
  3. rsync -a --delete 同步 data/uploads → NAS uploads/
  4. rsync 工作区 v2/* → NAS workspaces/
  5. tar 打包配置/密钥 → NAS config/<date>/，chmod 600
  6. redis-cli SAVE 后拷贝 RDB → NAS redis/
  7. 校验：pg_restore --list · gzip -t · 文件计数对比
  8. 写校验报告到 logs/，清理 14 天前的旧 dump
06

校验与恢复

备份后自动校验

pg_restore --list 验证 dump 可读、gzip -t 验证压缩完整、附件按文件计数对比源与目标。校验失败当日即告警，避免"备份了但没法恢复"。

月度恢复演练

每月在临时容器 docker run pgvector/pgvector:pg17 中 pg_restore 最近一份 dump，确认业务库可完整还原——备份的价值在恢复，演练证明恢复路径通。

决策与遗留

以下决策已定，方案据此落地：

项决策
OpenClaw 平台不纳入 · 仅备份 Multica 平台自身
WAL 归档增强档暂缓 · 先跑每日 dump，稳定后择低峰窗口升级
dump 保留周期30 天 + 月末归档
Redis 会话快照纳入 L5 · 每日 RDB 拷贝

遗留待确认（不影响核心备份落地）

  • D2
    NAS 组织数据（AI 平台 ~120G 等）冗余
    不在本备份目标内；建议与 NAS 管理员确认 RAID / 快照 / 异地同步。若全无，再单独评估关键目录增量拉取。
  • D6
    运营机自身状态（~/.claude 凭证与记忆、~/.agents/skills、Tavily key）
    非平台数据，可后续单独归档，不阻塞本方案。
