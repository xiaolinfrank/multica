2.1 · IMG#1 · L81–91

总体架构：四层 + 一条纵向运维带

业务视角的分层：用户入口 — 业务流转 — 能力中台 — 资源底座，右侧运维平台纵向贯穿全部四层。注意这与 2.2 的「五横两纵」是两套并列视图，不是同一张图。

※ 两个「五」不是同一个集合 冲突

五项存量标品（L13–23）= 可信数据空间 / 数据平台 / 模型管理 / 算力调度 / 运维平台　—— 不含智能体平台。

五大能力中台（IMG#1）= 数据平台 / 智能体平台 / 模型管理 / 算力调度 / 可信数据空间　—— 不含运维平台。

而 6.7「智能体平台集成方案」是一个只有标题、正文全空的章节。全平台的核心编排引擎，既不在标品清单里，也不在本期建设范围里，还没有集成方案。唯一线索是 L41–43 裸列的两份文档名：智能体平台_MVP技术方案_v1.0_技术向 / 智能体平台_MVP产品方案_v1.0。

※ 谁在调度资源？ 图

两版图都把空间创建与销毁的发起方放在「统一门户」，由门户下发指令给运维平台——门户承担了资源生命周期调度职责，文档未对这一非常规划分做任何说明。

更值得注意的是：IMG#7 / #8 / #9 / #10 四张运行时图里，「算力调度平台」一个泳道都没有。容器创建、代码执行、资源回收全部落在运维平台。算力调度平台在运行时图中唯一一次出场，是 IMG#13 的「可出域数据」分支。
