# 驾驶舱原生化评审记录：体验与可逆性（2026-10-12）

本文件记录 2026-10-12 对 `codex/cockpit-native-foundation`（HEAD `c9d552a1f`，80 提交）的两轮只读评审结论：①多维度体验评审（设计符合度 / 会议 UX / 资料输入 UX / 死按钮 / 概念与信息架构，附分组复核）；②确认动作可逆性审计（52 个确认动作逐一核查）。评审依据的原始数据为 workflow 输出，本文件为结论固化；全部发现均带代码证据，可按 file:line 复查。评审后的整改决策见[设计总纲](./design-principles-2026-10-12.md)。

## 一、设计符合度

**机制层兑现了原始设计的承诺；信息架构与体验发生系统性偏离。**

proposal §4.5 六条不可破坏约束：4 条完全守住（分层完成条件、单一权威写入位置、稳定身份+固定版本、command_key 幂等重放），2 条部分（关联不赋权的服务端核验未逐条完成；决议对象缺失导致约束 6 的决议分支未落地）。自报状态（implementation-status / completion-plan）抽查 5/5 属实，无假完成。

主要偏离：

1. **会议工作台形态反转**（最大单一偏离）。设计（proposal §9.3 / S05–S09）：阶段驱动全幅工作台，工作条「准备→会议记录→纪要确认→行动跟进」，每阶段一个明确主动作，基本信息折叠进辅助区。实现：46rem 侧面板内 4 个按数据类别划分的 tab（议题与准备 / 工作流 / 关联与资料 / 基本信息），默认落位「纪要工作流」tab；完成会后闭环跨 3 个界面层级、9 个 server 命令、约 16 步、多次 tab 往返；全能力开启时约 130 个按钮 / 50 个不同动作 / 26 处菜单；嵌套对话框 4–6 层。设计承诺的正文 ≥680px 工作台未兑现于会议场景。
2. **会中主持形态缺失**：会中仅剩讨论记录 textarea；设计的「记为决议建议 / 行动建议 / 关联任务」候选结论捕获未实现。
3. **决议对象整体未实现**：全 server 无 decision 实体，「准备→会议→纪要→决议/行动→跟进」决策链断在纪要发布处；治理面实际只有待审变更队列。
4. 行动处置缺设计 S09 的第四种处置「暂缓」；缺设计 §5.4 的整轮评审结果摘要。
5. 治理面词汇（governance_view 枚举含 decisions/risks/history/automation）无导航实现。

## 二、体验问题的结构性根因

**「按钮按下没反应」**：593 个按钮全量扫描，不存在传统死按钮（无空 onClick、无 TODO stub、无吞错）。真实原因是四类系统性模式（分组复核后确认）：

| 模式 | 规模 | 机制 |
| --- | --- | --- |
| 灰死且无解释 | 15 处主流程（54%） | disabled 由后台派生布尔组成（指派人可用性/操作基线/能力旗标/revision 确认），任一为 false 即灰死，原因不渲染 |
| 能力旗标静默移除 | 8 个布尔开关 | capabilities 为布尔无 reason，部署侧一个 env 缺失即可让五族功能一起消失且无法归因 |
| 刷新/重试无 busy 态 | 25+ 处 | React Query 去重期间点击无可见变化 |
| 防丢命令锁死表单 | 全部表单 | 模糊失败后表单锁死、恢复控件横幅散布，无全局「未确认操作」入口 |

另有：所有 inspect 动作关闭当前对话框整页跳转（工作上下文丢失）；对话框栈 4–5 层；会议资料 tab 同屏三套「材料」概念互不解释；分区名硬编码中文绕过 i18n。

**「概念看不懂」**：用户确认的核心词汇表 14 词（CONTEXT.md），UI 需学习名词已达约 55–70（4–5 倍）；zh-Hans cockpit.json 从 512 key 涨到 2188 key。三个膨胀来源：①词汇表的定义句被逐词实体化（会议定义句六动词 → 6 个 checkbox，措辞还与原文漂移）；②基础设施词泄漏进一级流程（受管根/材料分区/导出尝试/写入模式/传输 11 态机/固定 5 态/可读性 4 态）；③同物多名（会议台账四名、产出物五名、「纪要工作包/纪要工作流/工作流 tab」三名一物、「行动建议」与词汇表「行动项」同名异指）。33 个新术语判定中 12+ 个 unnecessary。

**「状态不清晰」**：一场会议的状态分裂在 ≥7 组并行状态机上（发生事实/自定义备注/工作包/版本 decision+published/NAS/准备操作/传输族），台账卡片无汇总进度，总进度呈现分散 5 处互不复述。

**「流程特别多」**：全流程开一场会（模板/议程/准备/目录）29 步（最短 9 步）；取消一场会 13 步；资料登记面约 200 按钮 / 100 动作。

## 三、确认动作可逆性审计（52 项）

分域结论：输入资料·成果·验收·治理域 24 项中可逆 17 / 部分 7 / **不可逆 0**——N2 输入系统是全分支最符合可逆原则的部分（清单全量替换追加、引用软删+新键重建、账本式来回、变更提案结果=普通字段直改）。会议域 27 项中可逆 15 / 部分 9 / **不可逆 5**。

实现事实上已采用「追加不可变记录 + 可移动指针」三层模型；问题集中在结论层指针**只能前进、不能回退或置空**。

五个不可逆与代表性单向点（证据见代码）：

| 确认动作 | 写死的内容 | 位置 |
| --- | --- | --- |
| 启动纪要任务（release） | released_at 全仓唯一写入口只写不清；执行门禁永久放行；readiness 冻结；会议删除被阻断 | cockpit_workflow.sql:19-22、cockpit_workflow_release.go |
| 确认结束（end） | occurrence_state=ended 与 ended_at 无任何回写路径；且 in_progress 状态连取消会议都被阻断，状态机单向棘轮 | cockpit_meeting_lifecycle.go:341-348、cockpit_cancellation.go:108-111 |
| 行动处置确认（resolve） | SQL 仅 status='draft' 可写，二次决议 409；dismissed 无任何路径变为 create/reuse | cockpit_actions.sql:19-27、cockpit_planning.go:202-213 |
| L3 验收「通过」 | last_approved_request_id 只有 SET 无 CLEAR；后续请求被拒也不清旧通过 | cockpit_acceptance.sql:17 |
| 启用纪要工作包 | 无 disable；接管 Issue 后不可换绑；启用后会议删除被阻断 | cockpit.go:2217-2219 |

单向指针（partial）代表：发布可替换不可下线（无 unpublish）；同版本评审结论一次性写入（推翻只能走新版本新轮次——记录层不可变属历史留痕豁免，效力层可推翻，此条达标）；材料齐备在 release 前可双向（做对了的样板）、release 后冻结。

设计契约层面：没有任何一份既有契约承诺「确认可逆」；相反，end/release/单版本结论/行动处置被刻意设计为终态（meeting-lifecycle-contract §2/§3/§5、work-package-contract、meeting-actions-contract、artifact-acceptance-contract），以「历史事实保护」换取可审计性——这是与[设计总纲](./design-principles-2026-10-12.md)原则 2 的结构性张力，也是本评审触发总纲修订的原因。

## 四、做对了的样板（重构时保留并推广）

- 材料齐备：同命令双向（materials_ready true/false），UI 即双向 checkbox。
- 生产责任转移 / 评审人交接：账本式任意来回，from/to/reason 全留痕。
- 任务输入清单：每次保存全量替换+追加版本，旧版本与旧 Run pin 永久可读。
- 输入/成果引用：软删+新键重建，可指向任意历史固定版本，永不自动跟随 current。
- 变更提案批准：applied 行终态留痕，但写入的 18 种计划字段全部可经普通编辑改回——「结果=可改字段」的正确形态。
- 快照恢复：restore 前同事务冻结被顶替板，天然可再恢复。
- meeting_issues 关联表（PUT/POST/DELETE + roles）：会议↔任务关联本身就是软的、多对多的——工作包是对它的背离，不是平台限制。

## 五、两轮评审的合流结论

UX 评审的「概念膨胀（unnecessary 术语大头是工作包/处置/门禁类实体）」与可逆性审计的「终态+门禁焊接」，同根同源：**把一组属性升格为实体（工作包）、把投影固化为状态机字段（released_at/enabled）、把关联焊接成从属（门禁/删除阻断）**。整改方向不是加机制，而是做减法——见[设计总纲](./design-principles-2026-10-12.md)重构清单。
