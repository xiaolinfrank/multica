## 当前并行分工

- 后端业务线：通用成果、固定版本、验收和正式 Review Issue，随后接决议及治理。复用附件存储能力，但不把按文件名分组的附件列表冒充正式成果版本。
- 成果模型已经区分不可变原始来源、当前生产责任与每版 Issue/Run/会议来源，支持跨 L3/会议的固定版本引用；依[真实接口合同](./artifact-runtime-contract.md)验收。文件私密能力单独判断，现有公开 S3 配置不能提交固定文件，仍可使用文本成果。
- UI 线：统一驾驶舱外壳、范围与各工作面；产出物和治理随真实服务一起接入，不交付空占位页面。
- NAS 线：显式 `atomic` / `create_only`，尝试账本、完成记录及真实文件验证；固定逻辑目标和核验成功的物理副本位置分开。
- 整合线：范围化读模型、客户端 API、CLI、原功能接线、数据纳管和最终验收。

## 实施约束

1. agent 3 是唯一运行和浏览器验收环境；协调机只编辑、编译和静态检查。常驻配置、用户新增数据和旧文件保留。
2. 沿用[交互断点合同](./interaction-recovery-audit.md)：条件有依据、问题有真实处理入口、修复往返保留草稿；没有实现的能力不得用假按钮或漂亮零值代替。
3. 新读取显式报告范围、计数和是否完整。计划树的汇总不能从不完整分页在客户端假算；超过完整范围预算时，提供缩小范围或分支读取入口。
4. 新功能的自动执行必须有明确授权、责任和范围；验收/正式决议仍依据人对指定版本的结论。默认验证不运行用户安装的真实 Agent CLI。
5. 按已审查的扩号方案继续实施：新增 fork 迁移改用 9000–9999；旧文件名和账本身份保留，runner 按数字前缀排序。NAS 的 989–991 与创建意图的 992–994 保持原名；成果/验收 9000–9064 及性能修正 9065 已在隔离测试库应用并冻结，详见[迁移实施方案](./implementation/migration-range-plan.md)。不能覆盖旧文件或删除旧账本来补表。
6. 生产发布作为最后的具体上线动作处理；先完成代码、agent 3 验收和完整发布材料。不得把“生产尚未发布”隐藏在完成宣称中。

## 当前数据读取合同

URL 的范围为 `project=<UUID>&module=<UUID>`，API 使用 `project_id/module_id`。模块必须属于选定项目；无效或已失效范围保持可见并提供修复，不静默变成全部项目。范围外深链对象可以明确只读查看，并由用户选择切换范围。

新界面分开读取驾驶舱基础信息、完整但有上限的范围计划、分页会议台账、当前日历窗口和单个对象详情。工作总览、任务、行动和纪要历史继续使用已有有界读模型。旧全板 API 只作为已安装客户端的外部兼容边界，不再作为新驾驶舱入口的数据源。

规模验证采用主提案的项目/L3/任务/会议样本，并明确设备、冷暖缓存、范围与结果；不能用数十条示例或 CSS 裁切代替大量数据验收。
