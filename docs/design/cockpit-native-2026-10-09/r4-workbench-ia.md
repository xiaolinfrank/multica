# R4：会议工作台信息架构重组（第一刀：阶段条与主动作）

状态：**第一刀已实现**（阶段条 + 每阶段主动作 + 阶段感知落位 + 「工作流」→「纪要」更名 + 历史记录折叠）。完整 S06–S09 三栏工作台（议题列表/当前议题/相关栏）与全幅布局留待第二刀。依据 [proposal §9.3](./proposal.md)、[ui-ux-design S05–S09](./ui-ux-design.md)、[设计总纲原则 3](./design-principles-2026-10-12.md)。

## 缺口

现状会议面板是 4 个并列 tab（议题与准备/工作流/关联与资料/基本信息），无阶段叙事：打开一场已结束待纪要的会议与打开一场未排期的会议落在同一个默认视图，用户要自己判断「现在该做什么」；「工作流」一词与总纲词汇治理冲突（应为「纪要」）。

## 第一刀改动

1. **阶段条**（`CockpitMeetingStageStrip`）：面板 tab 区上方渲染「准备 → 会议记录 → 纪要确认 → 行动跟进」。阶段是**纯投影**（`cockpitMeetingStage`，原则 3：不落库）：
   | 阶段 | 投影条件 |
   | --- | --- |
   | 准备 | occurrence ∈ {unconfirmed, scheduled} |
   | 会议记录 | in_progress |
   | 纪要确认 | ended 且发布指针为空 |
   | 行动跟进 | ended 且 `published_version_id` 非空 |
   cancelled 不渲染阶段条。每阶段可点击，落位对应分区。
2. **每阶段一个主动作**：准备「检查材料」（→关联与资料）、会议记录「结束会议」（→发生事实区，实心主按钮）、纪要确认「纪要任务」（→纪要）、行动跟进「未完成行动」（→纪要）。
3. **阶段感知默认落位**：URL 无 `meeting_view` 时，纪要确认/行动跟进落「纪要」tab，其余落「议题与准备」（原一律落「工作流」）。显式选择的 tab 持续由 URL 承载，不受 query 后到影响。
4. **词汇**：tab「工作流」→「纪要」（四语：纪要/Minutes/議事録/회의록）。
5. **历史记录折叠**：details tab 的旧自由文本区（minutes/decisions/actions）默认收起（`<details>`），事实层入口在议题与准备 tab。
