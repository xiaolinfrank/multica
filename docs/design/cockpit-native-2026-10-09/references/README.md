以下“建议”是结合 Multica 任务场景的设计判断，并非原作者对 Multica 的建议。

| 参考 | 实际所见 | 驾驶舱可采用的原则 | 需要调整的部分 |
| --- | --- | --- | --- |
| 1：神经网络面板 | 中心与模块、内容节点逐层展开，右侧显示当前内容分析；界面强调来源、双向联系；视频强调逐轮明确交互并检查实际效果 | 从 L3 执行任务展开会议、任务、决议与产出物；详情侧栏保留甘特图与筛选上下文；每条关系可说明含义与来源 | 图谱作为关系检查视图；默认首页不能把密集管理对象全部变成漂浮节点；图谱不能替代清晰的表格与状态 |
| 2：六种菜单 | 滑动高亮块、就地展开子菜单、顶部横排下落面板、底部停靠栏、命令面板、状态点与计数徽标 | 内部 tabs 保留文字、明确选中；只显示真实待处理计数，导航与操作层级分工 | 不将六种范式全部叠加，不加第二套平台侧栏；实际第六项是状态点与计数徽标，不据分享文案写成悬停预览 |
| 3：浅色企业工作台 | 大面积浅灰白，卡片围绕一个主体，数字与图表分区；一个案例含横向周日程；主体为机械臂或脊柱的 3D 模型 | 首页建立视觉主次：关键项目状态、待决事项、里程碑、会议与产出物；会议可采用周日程加当日详情的分栏 | PMO 没有对应的实体模型，不应为装饰制造巨型 3D 中心；空间应交给可操作的执行脉络 |

## 建议的视觉决策

1. 驾驶舱采用浅色、清楚的层次和克制强调色；全平台既有外壳保持一致。本轮视觉改造限定在驾驶舱及内部标签页。
2. 首页布局由工作优先级驱动：先显示需要人决定的事项、执行风险和下一里程碑，再提供会议、任务和产出物的入口。卡片点击后进入同一筛选范围。
3. 执行甘特图、会议日程、任务表格和产出物列表共享对象详情侧栏；切换视图时保留项目范围、所选 L3、筛选条件和滚动位置。
4. 关系图保留“选中对象的一跳关系”，按关系类型筛选；默认聚合，避免大量长期任务形成不可维护的全量网络。
5. 工作模式强调高密度、操作与可追溯；展示模式降低密度、强化读数与里程碑，使用同一事实来源，不另外维护一份演示数据。
6. 屏幕阅读、键盘、触摸、减少动态效果、长中文标题和空/错/加载状态作为完整设计的一部分；不直接复制参考中的小号灰字、弱对比或纯悬停触发。
