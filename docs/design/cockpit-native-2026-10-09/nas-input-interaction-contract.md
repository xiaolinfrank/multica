# NAS 输入资料与目录准备：交互实施草案

日期：2026-10-11。状态：**设计草案，未实现、未验收**。本文件收敛 [NAS 专项设计](./nas-workspace.md) 的 N1 / N2，以及[交互恢复审计](./interaction-recovery-audit.md#会议议题批次及-nas-下一步2026-10-11)所列断点。阶段 L 模板、取消和归档产品继续冻结；本文件不改变其接口或发布范围。

本文定义入口、呈现、确认与恢复要求，不指定已存在的新表、路由、命令名或权限字段。实现前由领域与 core 合同确定具体 DTO、预算和服务能力。自动目录观察、转写、OCR、批量历史导入和跨主机调度不因本草案而视作可用。

## 1. 现状及本批目标

| 已核实路径 | 当前事实 | 本批要补齐的动作 |
| --- | --- | --- |
| 会议 → 关联与资料 → 材料工作区 | [材料组件](../../../packages/views/cockpit/components/cockpit-meeting-materials.tsx)提供纪要任务、会议说明和 NAS 路径；没有纪要任务时引向工作包配置 | 无工作包也能登记原始录音、照片、文档，并选择是否作为某议题或任务的输入 |
| 会议 → 添加固定成果 → 成果工作台 | [固定成果入口](../../../packages/views/cockpit/components/cockpit-meeting-add-artifact.tsx)可以复用真正的成果版本；[成果登记](../../../packages/views/cockpit/components/cockpit-artifact-create.tsx)需要 L3、来源任务和评审人 | 保留成果路径，同时新增独立输入登记；不能为了保存一段录音而强迫建立交付成果或评审任务 |
| 会议 → 准备资料目录 | [旧 provision](../../../server/internal/handler/cockpit_meeting.go)可能保存已成功的基目录，同时返回子目录错误；未形成持久的逐步骤结果 | 区分会议、任务与目录结果；继续处理同一目录准备记录中的缺失步骤 |
| 目录已绑定后的材料工作区 | [路径控件](../../../packages/views/cockpit/components/cockpit-path-field.tsx)仅在路径为空时显示附加创建按钮 | 路径存在仍可检查目录、查看缺失分区并修复，不要求先清空路径再重建 |
| 打开目录 | [现有本地路径组件](../../../packages/views/common/local-path-link.tsx)按设备打开或复制 SMB / UNC / 本地地址，浏览器无法证明文件管理器已成功挂载 | 分开显示“本设备打开方式”和“执行端读取检查”，不能把复制成功当成 NAS 可用 |
| 目录扫描导入会议 | 当前扫描用于发现会议目录、人工纠正登记信息 | 文件级手动选材必须有独立、有界入口，不能把会议目录导入说成材料摄取 |

验收目标是：从一场无工作包、无 L3 的会议出发，用户能保留原始材料、看清固定结果、将选定版本交给已有任务；目录仅部分成功时能找到准确重试动作，且不会生成第二个任务或覆盖原文件。

## 2. 对象与用语

- **输入资料**：一次业务登记，具有稳定身份、名称和来源。可以属于会议或项目，L3、议题、处理任务均为显式可选关联。登记不要求成果评审人，也不创建 Review Issue。
- **输入版本**：已核对并可再次取得的固定内容。记录来源文件或附件身份、内容标识、大小、固定时间和操作者；只有内容哈希或可变 NAS 路径不足以称为固定版本。
- **位置参考**：一个目录或文件位置提示。允许保留为参考，但明确“尚未固定内容”，不能作为可用输入版本、批准证据或任务材料齐备的证明。
- **任务输入清单**：人明确选择的版本集合及用途、必要性。材料登记与加入某个任务清单分别确认；从任务入口发起时可以在同一次可审阅确认中完成两者。
- **本次运行输入**：某个真实 Run 启动时确认的清单修订。后来的材料更新不能替换这一记录。未接入真实运行快照前，只能称“任务选定资料”，不能声称该运行已经使用。
- **目录准备记录**：同一业务对象、已确认目标与分区计划的持久操作。记录各步骤的实际结果，与任务派发、材料确认、正式成果发布分开。

已有固定成果仍按其实际版本、评审状态和引用关系展示。“待评审的成果可作讨论材料”不等于“已批准的验收证据”。原始输入日后形成转写、纪要或分析成果时，另走既有成果提交与人工评审，并保留输入版本来源。

## 3. 入口与返回

不新增驾驶舱顶层 tab，也不重绘全局侧栏。

| 入口 | 默认目标与可见操作 | 返回规则 |
| --- | --- | --- |
| 会议 → 关联与资料 → **输入资料** | 当前会议固定；“上传原始资料”“从 NAS 选择”“关联已有资料”。无 L3、纪要任务、评审人仍可进入 | 保存后留在当前会议并显示本次结果；关闭保留会议、议题、范围、搜索和滚动 |
| 议题 → 准备与材料 → **选择输入资料** | 当前议题固定，从当前会议已登记输入版本中选择；空态给“登记输入资料”入口 | 登记结果返回原议题待选择清单，仍需明确关联；不顺便创建准备任务 |
| 会议 → 资料目录 | 已绑定与未绑定都显示“检查目录准备”；只有真实缺失步骤才显示“补齐缺失目录” | 回到同一准备记录，不跳回创建会议或初始化纪要任务 |
| 纪要或准备任务 → 输入资料 | 当前已解析 Issue UUID 固定；选择资料版本、查看缺口、打开原会议 | 外部来源用明确的新标签链接；原任务编辑和未提交选择保留 |
| L3 → 资料与产出 | 展示已显式关联的输入与成果，两类有标签 | 不因人在某 L3 视图就强制把项目级原始资料迁入该 L3 |
| 治理 → 资料空间配置 | 查看受管根、执行端与挂载检查；有实际管理能力时才进入编辑 | 返回原会议的未完成准备记录。没有配置编辑器时提供真实配置说明，不显示空操作页 |

后续统一来源展示时，来源任务或运行必须有准确的查看入口；只显示 Agent 与授权人姓名不足以追溯。区分原始发起来源、当前负责人和当前授权，不根据名字相同把这些角色合并。目录准备已有这些后台字段，后续与输入资料沿同一来源入口接通；没有真实 Issue/Run 来源的人工操作不制造链接。

材料工作区顶部只显示业务摘要与主动作，例如“3 项可用输入 · 1 项待处理”“打开资料目录”。根路径、执行端挂载、哈希、操作键和历史尝试放在明确的“来源与核验详情”中；失败原因和下一步修复入口始终可见。

## 4. N1：可靠目录准备

### 4.1 首次准备与接管旧目录

首次准备先显示服务端解析的目标根、业务目录、现有与待建分区，默认沿用“会议纪要与录音转写”“会议材料”“照片”。本次目录操作只创建明确授权的缺失分区，不移动已有文件，不重新创建已存在的会议或 Issue。

已有 `nas_dir` 的旧会议可以先“检查并接管准备记录”。这是检查当前绑定，不是从改名后的会议标题重新推导路径。目录存在不代表所有分区可用，也不代表操作者拥有写权限。旧目录中同名文件、符号链接、权限限制或无法证明的根身份分别报告，不能把它们当作可创建的空目录。

用户在“创建会议”中同时选择任务与目录时，确认页分开列出将建立的业务对象及外部步骤。会议和任务的已确认结果立即可打开；目录失败不使整个表单退回“未创建”。重试入口固定原会议、原任务与原目录计划。

### 4.2 状态 → 下一步

以下是界面语义，不预设服务端枚举名称。

| 状态 | 显示事实 | 主要动作与限制 |
| --- | --- | --- |
| 未绑定目标 | 未选受管根或业务目录 | “选择已有目录”或“预览目录准备”；无配置权限者可查看配置负责人及说明 |
| 尚未检查 | 有路径但没有有效执行端检查 | “检查目录准备”；允许复制已登记位置，不显示已就绪 |
| 等待连接 | 指定执行端或共享根不可达 | “重新检查连接”“查看连接说明”；不自动创建同名本地根来掩盖掉线 |
| 缺少写权限 | 指定目标可读但不能创建分区 | “查看所需权限”“重新检查”；已有可读资料仍可查看 |
| 部分完成 | 例如 4 个步骤中 2 个已确认，2 个失败 | 已完成项保持成功；列出缺失分区，提供“重试这一步”及明确的“重试这 N 个缺失步骤” |
| 全部完成 | 本次计划各步骤已核验 | “打开资料目录”“选择输入资料”；材料齐备仍由人单独确认 |
| 目标变化或名称冲突 | 当前绑定、根身份或目标形态与原计划不符 | 对照原目标和实际情况；“保留原目标重新检查”或明确建立新计划，不静默换目录继续 |
| 结果未知 | 请求可能已执行但没有可信回执 | “核对上次操作”；保留原命令，读回确认前不生成新操作键或新 Issue |
| 权限被撤回 | 当前操作者不能执行后续步骤 | 保留历史与草稿，暂停新写；有权限的人显式接手，原操作者可查看的既有结果不伪装为空 |

目录步骤的尝试历史按 25 条分页，默认显示最后结果。一个步骤最多呈现真实的已完成量，不用目录数量估算百分比。重启后继续读持久记录；迟到旧尝试不能覆盖新尝试，也不能将用户从另一会议带回。

### 4.3 目录与任务严格分离

重试子目录不能调用“再次建立纪要任务”。目录准备记录包含已确认任务的稳定链接，任务失败也有自己的恢复入口。若原任务已删除或因权限不可读，应明确提示核对，不根据标题搜索后猜测复用，更不自动重建。

会议取消或归档后默认暂停新增输入与新目录准备；历史读取、原结果核对仍可用。恢复入口走已存在的会议操作，解除归档或重新安排不会自动运行任务或回放旧目录计划。具体“已有缺失步骤是否允许仅修复”的权限由服务端能力明确返回，UI 不以归档状态自行放宽。

## 5. N2：手动选材与输入登记

### 5.1 三种来源，同一确认结果

1. **上传原始资料**：直接选择录音、照片或文档，显示文件名、类型、大小、目标会议或项目；可选关联议题和已有处理任务。不要求先新建隐藏的承载 Issue，也不强迫交付 L3 或评审人。上传中断保留可恢复会话或明确的重新选择要求，不能宣称浏览器重启后仍握有本地文件句柄。
2. **从 NAS 选择**：先显示已授权的根与业务目录，逐层浏览或在该受管范围内搜索。每次只读一页元数据，不自动递归扫描整盘。用户勾选后才进行稳定性检查、固定内容与登记。
3. **关联已有资料**：选择已有输入的固定版本，或复用既有成果固定版本。已有 Issue 附件可以作为来源候选，但先核其真实 Issue / 工作区与读取权限；不把评论下所有附件自动加入输入。

确认页最多 50 个条目，摘要区分“新增输入”“复用已有版本”“仅位置参考”“不可登记”。每条显示目标、来源、所见文件时间与大小、将执行的复制或引用，以及是否加入某个任务。服务器若支持更低预算，以真实能力收窄；不把超限的剩余条目悄悄排除。

同名文件不能默认覆盖。相同内容可提示已有版本，但只有用户有权读取且目标关系允许时才能复用；内容哈希相同不会自动合并不同项目的材料身份。

### 5.2 内容状态 → 下一步

| 状态 | 主入口与处理 |
| --- | --- |
| 可选择、未固定 | “登记并固定此版本”；不显示为可运行输入 |
| 正在写入或大小变化 | “稍后重新检查”；保留已选项，暂不固定、不转写、不派发 |
| 正在固定 | 显示真实阶段；只有有可测字节进度时显示数值，避免虚构百分比 |
| 已固定且可读取 | “查看 / 下载此版本”“加入任务输入清单”；同时可打开原始位置 |
| 来源已变化 | 对照本次观察与现在的文件；“重新检查后登记新版本”或保留旧固定版本，不能在原确认下换内容 |
| 来源丢失、固定副本仍可读 | 历史版本仍可使用，标记来源位置不可用，提供“重新定位来源”；不撤销其历史事实 |
| 来源或固定内容当前无权读取 | 说明权限问题并保留可见元数据；“重新核验”与真实来源 / 配置入口，不以空列表表示已删除 |
| 固定存储不可用 | “重新核验”“查看存储配置说明”；保留原件或位置参考，不能假称已固定 |
| 超出本部署大小或类型能力 | 紧邻条目说明实际限制；可打开目录、保留位置参考或选可支持文件，不重复给无效重试按钮 |
| 部分成功 / 结果未知 | 分别展示已确认、失败和待核对条目，成功项可直接打开；仅针对未确认的原条目继续，保留修正输入 |

“重新核验”是显式读操作，不自动采用新的内容、重启后台任务或形成新的审批轮次。大文件走经部署验证的受控流式读取、固定副本或上传会话；不把已有工作目录下载中继、消息通道或 heartbeat 当作通用录音传输能力。

### 5.3 任务输入清单与人的准备确认

任务清单以稳定输入版本 ID 保存，每项有人可读名称、版本、用途和“必要 / 可选”。服务端提供全清单的缺失及不可读统计，界面按 25 条展开；不从当前页推断“全部齐备”。

清单编辑采用观察修订与显式确认。另一人修改时保留我的选择和说明，显示已移除、已更新或不可用项；只有重新核对后才用新修订提交。批量添加可跨页保留选择，但不得把未读页面的全部资料默认勾选。

纪要工作区在“材料已齐备”旁展示“查看本次输入清单”与真实缺口。此布尔仍是人的业务确认：文件可读、准备 Issue 完成或目录在线都不能自动勾选。无需完整清单也可继续登记与讨论；准备执行时是否因必要资料缺失受阻，由具体任务能力与服务端规则说明。

已有 Run 若真实绑定了输入清单修订，可按需显示其固定清单和输出位置。新材料到达只显示“有更新可用于下一次运行”，不覆盖旧 Run、既有成果版本或正在评审的依据。原运行未记录清单时明确“未记录固定输入清单”，不能按当前清单倒填历史。

## 6. 可读位置、权限与设备差异

检查结果分三层呈现：

1. **业务访问**：当前人是否能读会议、任务、资料与目标范围；不能用历史链接替代当前鉴权。
2. **存储能力**：受管根、实际执行端、最后成功检查、当前可读 / 可写 / 固定能力。根未挂载与路径不存在分开，不能检测到同名空目录就认为连接正常。
3. **本设备入口**：支持时打开 Finder / Explorer；不支持时复制真实可用地址并说明下一步。成功复制地址不改变服务端状态。

路径、挂载映射和执行端身份默认在详情中；有故障时相关事实直接出现在错误旁。未配置根和已配置但掉线给不同动作。管理权限从服务端事实取得；有真实配置表单时才显示“配置”，否则显示已有的配置说明与责任人信息，不提供虚假的设置链接，也不自动发消息给管理员。

NAS 文件和文件内清单都是资料，不是程序指令或权限授权。界面不能宣称一个输入清单限制了拥有整个挂载权限的 Agent shell。若执行端隔离尚未实现，必须如实显示其实际访问边界；首次手动选材不附带自动执行授权。

## 7. 数据与规模边界

- 所有增长列表默认 25 条：目录条目、搜索、输入资料、版本、任务输入、操作和尝试历史。正文、内容预览和下载只在打开单对象后获取。
- 一个浏览动作只打开一个目录；搜索必须回显受管范围。无准确总数时显示“已显示 N 项 / 继续读取”，不能拿本页长度充当全目录数量。过期游标提供“回到首页并保留已选项”。
- 单次确认最多 50 个文件 / 关联，执行按后端明确的有界协议推进。后台每项有稳定身份与实际回执；不并发无限读取大录音，也不把不同目标的成功混成一个全成功状态。
- 已选对象恢复按 ID 批量读取，缺项明确保留为需处理，不逐行读取所有候选的正文，不扫描全历史寻找一次命令回执。
- 名称在列表最多两行，详情标题默认有限行并可展开；长路径和核验信息折叠。390px 下确认摘要、当前条目及下一步按钮可触达，详情继续沿当前会议聚焦布局。
- Query 管服务器事实；core 草稿只存用户输入、稳定选择 ID、观察修订与未确认命令。工作区、账号和操作代次隔离；登出清理，A→B→A 迟到响应不关闭新表单、不清新选择。
- 正式错误、响应未知与已确认成功分开。明确拒绝后旧确认失效，需要显式新预览；未知结果先按原键读取，不自动换键，不把关闭提示说成取消已完成的外部操作。

## 8. 实现前需冻结的最小读写语义

以下是下一批 API / 领域合同必须能表达的内容，尚不是路由或字段清单：

| 合同 | 必需事实或回执 |
| --- | --- |
| 空间与连接只读投影 | 稳定根 / 业务范围 / 实际执行位置、验证时刻、连接与读写能力、错误分类、真实恢复目标；不返回凭证 |
| 目录计划与逐步结果 | 明确原目标、计划修订、存在 / 待建分区、每步实际路径及尝试；原命令单读，任务关联独立于目录结果 |
| 有界文件候选 | 授权范围与目录回显、稳定候选身份、可见元数据、观察修订、游标与预算；不把任意客户端路径升级为授权根 |
| 输入登记与版本详情 | 独立于成果评审的身份、来源事实、固定内容状态、按需读取能力、精确原命令回执；不能仅返回“最新版本”来确认历史重放 |
| 显式关联与输入清单 | 会议 / 议题 / Issue 的实际关系、集合修订、全清单缺口统计和逐页内容；删除引用不删除原资料或历史输入 |
| 运行输入事实 | 实际运行绑定的固定修订及输出约定；未实现此绑定时保持未知，不由 UI 猜测 |
| 部分成功与恢复 | 已完成 / 拒绝 / 未尝试 / 待核对的逐项结果；权限变化和目标变化的明确原因及回读，不让重试重复创建业务对象 |

原始输入与成果可以复用经验证的私有固定存储、流式读取、哈希与短时下载能力，但不复用“必须有 L3 / 人工评审人”的成果创建门禁。旧公开附件与受管 NAS 来源是否具备安全固化能力应由真实部署能力声明，不由 UI 以路径后缀或目录名称判断。

## 9. 交付次序与验收

按当前实施顺序，先完成 **N1 目录准备恢复**，再实现 **N2 独立输入身份、浏览器直接上传、手动有界选材、固定内容与任务清单**。N1 的准确状态和接口以[目录准备运行合同](nas-directory-runtime-contract.md)为准；本稿中的输入资料流程正在实现，尚未完成验收或发布。自动观察与 AI 处理在手动链路和授权边界完成后另行接入，不为首片增加默认转写、自动归类或历史派发。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 无 L3、无工作包的会议登记一段录音和两张照片 | 不要求评审人；不创建 Review Issue；版本固定结果可查；新增任务和 Run 为 0 |
| 基目录及一个分区成功，另两个分区失败 | 已有路径下仍显示修复入口；重启后只补缺失步骤；会议和原 Issue 数量不变 |
| 创建目录成功但回执丢失 | 读原命令核对成功；无第二目录计划、无重复任务；返回路径与草稿保留 |
| NAS 掉线后本地留下同名空目录 | 检查失败且不写入冒名根；连接恢复后显式重验再继续 |
| 31 个候选文件、27 个已选输入 | 25 + 6 分页且不下载正文；跨页选择可核对，失败游标可回首页不丢选择 |
| 选中后文件仍在写入或发生替换 | 原确认不能固定新的字节；明确重验，不派发处理任务 |
| 登记批次部分成功、部分未知 | 已成功条目可直接打开；只核对或修复剩余原条目，失败草稿不清空 |
| 来源删除而固定副本仍有效 | 旧输入版本仍可读；来源失效单独提示，不伪撤销旧批准或旧 Run 的事实 |
| 原始输入加入已有任务清单 | 显式清单确认，不复制该任务全部附件，不自动勾选材料齐备或启动执行 |
| 执行中新增输入版本 | 本 Run 依据保持；下一次可选择更新，不能改写正在评审的来源 |
| 权限变化、跨工作区切换、A→B→A 晚回执 | 未授权写入被阻止；当前界面不跳转、不失稿，旧回执仅结算其原命令 |
| 归档会议继续查历史资料 | 历史入口可用；新增动作给真实恢复路径，解除归档不重启旧任务 |
| 390px 中文暗色、长文件名和长故障原因 | 主动作和返回可见，完整名称可展开，无路径墙、遮挡或整页横向溢出 |

本草案只做文档和源码引用核对，不计作功能验收。实现验证沿仓库规则在 agent 3 执行；真实 NAS 写入限定明确授权的隔离根和自有测试文件，使用真实 Agent 另需既有专门授权，不能在资料验收中隐含启动。
